# 架构文档：ata-Annotation-Scripts

本仓库是 16 个 Tampermonkey 脚本的演进集合，核心解决一个问题：**把标注平台分散在多个接口、多个状态、多个人身上的数据，聚合成可读、可对齐、可导出的进度与质量视图**。

文档拆解几个有代表性的技术机制（均来自真实生产脚本的工程实现）。

## 一、总体架构：浏览器端数据管线

每个脚本是一条独立管线，不依赖后端改造：

```
┌────────────┐   ┌────────────┐   ┌──────────────┐   ┌──────────────┐
│ 平台页面     │ → │ fetch 接口   │ → │ 时间滑窗硬过滤  │ → │ 双核质量计算   │
│ (SPA路由)   │   │ 原始数据     │   │ (1/3/7/14天)  │   │ (首次验收/折损) │
└────────────┘   └────────────┘   └──────────────┘   └──────┬───────┘
                                                            ↓
                        ┌──────────────┐   ┌──────────────┐   │
                        │ 协作文档智能粘贴│ ← │ 锚点对齐+占位  │ ← │ 面板渲染(UI)  │
                        │ 本地Excel导出 │   │ (ID双轨映射)  │   │              │
                        └──────────────┘   └──────────────┘   └──────────────┘
```

## 二、核心机制拆解

### 1. SPA 路由巡航雷达
标注平台是单页应用（SPA），切换路由时页面 DOM 被替换，常规注入的面板会"随路由消失"。

实现思路：
- 通过 `MutationObserver` 监听 DOM 变化，检测面板是否仍挂载
- 路由变化后自动**重新注入**面板，且通过 `window.tmUserEventsBound` 标志避免事件重复绑定
- 保证聚合结果在页面跳转后不丢失、不重复

### 2. ID 双轨映射引擎
多人可能同名、同 ID 可能出现在不同接口——直接按姓名或按 ID 归并都会产生"错误合并"。

实现思路：维护**ID ↔ 姓名 双轨映射表**（`assigneeMap`），聚合时以稳定的内部 ID 为键、以姓名为展示键，杜绝重名合并错误；同时支持同一人在多接口的增量数据累积。

### 3. 时间滑窗硬过滤
支持 1天 / 3天 / 7天 / 14天 / 历史全量 五种窗口。

实现思路：在**前端对拉取到的每条记录做时间硬过滤**（而非后端参数），拦截器在数据流进入聚合前剔除窗口外数据——这样即使接口只返回全量，也能得到任意窗口的准确口径。

### 4. 双核质量引擎
一个核心洞察：**"通过率"有两种可信口径**。

- **首次验收通过率**：只看第一次验收的通过与错误。用于对比供应商质检通过率，**识别"初标质量"与质检标准是否对齐**（防质检放水）。
- **累积折损通过率**：把所有历史返工（驳回→重做）计入基数。量化"达成最终交付**真实消耗的审核成本**"——返工越多，折损通过率越低。

实现方式：解析记录里的 `[验收统计]` / `[质检统计]` 结构化文本（正则提取 正确/错误 数），分别累计：
```
首次验收通过率 = 首次验收正确 / (首次验收正确 + 首次验收错误)
累积折损通过率 = 总验收正确 / (总验收正确 + 总验收错误 + 历史返工错误)
```
两种口径并行展示，同一数据看到"初标质量"与"交付成本"两个维度。

### 5. 锚点对齐 + 智能粘贴
固定全量人员名单作为**锚点**，无任务的成员自动用 `—` 占位——保证每行列数一致、导出到 Excel / 协作文档（腾讯文档/飞书）时列对齐不串位。

导出路径：`本地 Excel 下载` 与 `剪贴板智能粘贴`（保留制表符对齐，粘贴即表格）。

## 三、版本演进逻辑

脚本从 V1.6 到 V3.2.1 的演进主线：

| 里程碑 | 引入的能力 |
|---|---|
| V1.6 ~ V1.8 | 基础进度汇总、脱敏整理 |
| V1.9 ~ V2.0 | 首次质检+验收双率 |
| V2.1 ~ V2.3 | 看板协同、**双核质量引擎**、ID 双轨映射 |
| V2.4 ~ V2.6 | 人员能效、双核开源化 |
| V3.0 ~ V3.2 | **时间滑窗硬过滤**、锚点对齐、协作文档智能粘贴 |

## 四、与后端 Python 工具的分工

本仓库（JS 采集端）负责**从浏览器采集并标准化**数据；配合 [pm-automation-toolkit](https://github.com/liuhao-hn/pm-automation-toolkit)（Python 汇总端）做**跨供应商日报/周报**，形成"采集 → 汇总 → 分析 → 推送"全链路。
